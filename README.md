# Tokemon

윈도우 데스크톱에서 1세대 포켓몬 #001~#151을 선택해 키우는 Electron 앱입니다. 레벨 진화와 진화의 돌·연결의끈을 사용하는 아이템 진화를 지원합니다.

우클릭 → **포켓몬 선택 · 1세대**에서 번호 구간과 포켓몬을 고르세요. 선택한 시작 포켓몬별로 EXP와 진화 상태가 저장됩니다. 이상해씨를 키워 이상해풀로 진화시킨 기록과 이상해풀을 직접 선택한 기록은 별개입니다. 사용량 EXP는 현재 선택한 포켓몬에게만 들어갑니다. 기존 피카츄·라이츄 저장 파일의 모습과 EXP도 유지합니다.

## 실행

### Windows 실행 파일

v0.6.0 빌드 결과는 `dist/Tokemon-0.6.0-win-x64.exe`이며 [최신 릴리스](https://github.com/insu0929/tokemon/releases/latest)에서 받을 수 있습니다. 상점·가방과 아이템 진화, 첫 연동 시 누적 사용량 합산, 음소거 버튼, 앱 아이콘을 추가했습니다. 별도 임시 프로필로 실제 실행 파일의 151종 리소스·아이템 이미지 디코딩, 음소거 버튼, 오프라인 동작 검사(`node scripts/packaged-smoke.cjs`)를 통과했습니다.

v0.5.0 빌드 결과는 `dist/Tokemon-0.5.0-win-x64.exe`이며 [v0.5.0 릴리스](https://github.com/insu0929/tokemon/releases/tag/v0.5.0)에서 받을 수 있습니다. 151종 이미지·울음소리를 포함하며, 별도 임시 프로필로 실제 실행 파일의 전체 리소스 디코딩과 오프라인 동작 검사를 통과했습니다.

v0.3.0 빌드 결과는 `dist/Tokemon-0.3.0-win-x64.exe`입니다. Windows x64용이며 Node.js 설치가 필요 없습니다. 두 몬스터의 이미지와 울음소리, 레벨업·진화 효과음을 포함합니다. 위치와 성장 기록은 `%APPDATA%/Tokemon`에 저장합니다.

v0.3.0은 빌드 PC에서 포터블 exe를 네트워크 없이 실행하는 검사(`node scripts/packaged-smoke.cjs`)를 통과했으며 [최신 릴리스](https://github.com/insu0929/tokemon/releases/latest)에서 받을 수 있습니다. v0.2.0은 당시 빌드 PC의 Windows Application Control 정책으로 exe 실행이 차단되어 배포 검증을 하지 못했고, 정식 릴리스하지 않았습니다.

이 실행 파일은 코드 서명되지 않았습니다. Windows에서 게시자 확인 경고가 표시될 수 있습니다.

개발 환경에서 `npm.cmd install` 후 `npm.cmd run build:win`으로 다시 만들 수 있습니다. 빌드 결과는 `dist/`에 생성됩니다.

### 소스 코드 실행

Node.js 설치 후 이 폴더에서 실행합니다. PowerShell 실행 정책과 관계없이 `npm.cmd`를 사용할 수 있습니다.

```powershell
npm.cmd install
npm.cmd start
```

- 왼쪽 클릭: 현재 몬스터의 울음소리. 재생 중 연속 클릭은 무시합니다.
- 왼쪽 버튼으로 드래그: 화면에서 위치 이동. 드래그 종료 시 울지 않습니다.
- 포켓몬 오른쪽 아래의 작은 스피커 버튼: 클릭하면 음소거 켜기·끄기(우클릭 메뉴의 음소거와 연동), **길게 누르면 볼륨 슬라이더**가 열리고 바깥을 누르면 닫힙니다. 볼륨은 울음소리·효과음·진화 BGM에 함께 적용되며 이 PC에 저장됩니다.
- 오른쪽 클릭: 151종 포켓몬 선택, 음소거, 사용량 연동(체험 / Claude / Codex), 위치 초기화, 성장 초기화, 종료.
- 마지막 위치는 다음 실행에 복원됩니다. Alt+F4로도 종료할 수 있습니다.
- 말풍선과 하단 HP 바는 몬스터 표시 폭에 맞춰집니다. 아래의 **잔여량 체험** 슬라이더로 상태를 확인할 수 있습니다. Codex를 연동하면 HP가 실제 남은 한도를 따르고, 그 외에는 슬라이더로 조절하며 실행 시 100%로 시작합니다.
- 70~100%: 활발(빠른 움직임·점프), 50~70% 미만: 정상, 10~50% 미만: 약해짐(느린 움직임), 1~10% 미만: 기절(정지하며 쓰러짐). **체험 모드에서 잔여량을 0%로 내리면 포켓볼에 들어가며, 1% 이상으로 올리면 다시 나옵니다.** 체험 슬라이더는 EXP에 영향을 주지 않습니다.
- 상태 변경과 클릭 시 기본 울음소리의 속도·음높이·볼륨을 바꿔 재생합니다. 기절 중 클릭은 무음이고 기절 상태 진입 때만 울어요. 원작의 상태별 전용 음원·이미지가 아닌 앱의 연출입니다.
- OS의 동작 줄이기 설정에서는 반복 애니메이션을 멈춥니다.
- 이미지·음원은 `assets/`에 포함되어 있습니다. 누락된 경우에만 인터넷으로 다운로드합니다.
- 투명한 작은 창을 일반 앱 위에 표시합니다. 독점 전체화면 게임이나 Windows 보안 화면 위의 표시는 보장하지 않습니다.
- 이 MVP는 작은 사각형 창 영역에서 마우스 입력을 받습니다. 투명한 픽셀 단위 클릭 통과는 아직 구현하지 않았습니다.

## 범위

151종 이미지·울음소리, 52개 레벨 진화 연결, 20개 아이템 진화 연결, 상점과 가방, EXP 및 레벨, 드래그 이동, HP 바와 잔여량 체험 슬라이더, 네 가지 상태에 따른 애니메이션·음원 변형, Claude Code·Codex 실제 사용량 연동을 제공합니다. 모든 포켓몬에 포켓볼 복귀·재등장, 음소거, 위치 저장을 공통 적용합니다. Claude 남은 한도 연동, 배틀, 자동 업데이트는 포함하지 않습니다. 다른 OS는 검증하지 않았습니다.

## 가방과 상점

- HP 아래 **가방 / 상점** 버튼 또는 우클릭 메뉴로 엽니다. 상점에서 구입한 아이템은 가방에 쌓이며, 사용할 수 있는 아이템에는 현재 포켓몬의 진화 결과가 표시됩니다. 사용하면 1개가 소모되고 기존 진화 연출이 재생됩니다. 휴식 중에는 모습과 기록을 바로 갱신합니다.
- 새로 집계되는 사용 토큰은 **1토큰 = 보유 토큰 1개**로 EXP와 함께 적립됩니다. 체험 입력도 같은 방식입니다. 구매는 보유 토큰만 차감하며 EXP·레벨·서비스의 실제 사용 한도에는 영향을 주지 않습니다.
- 모든 아이템은 우선 **100,000토큰**입니다. 가격은 `src/tuning.cjs`의 `evolutionItemPrice`, 진화 대상은 `src/items.cjs`에서 조정합니다.
- **체험 모드**에서는 가방/상점 상단의 **체험용 보유 토큰 설정**에 원하는 잔액(0~1조)을 입력하고 **잔액 설정**을 누르세요. 기본 입력값 1,000,000이면 모든 아이템을 시험할 수 있습니다. EXP는 바뀌지 않습니다. Claude/Codex 연동 모드에서는 이 입력을 숨기고 메인 프로세스도 설정 요청을 거절합니다.
- 체험과 연동 모드는 기존 성장 기록처럼 같은 가방·잔액을 사용합니다. 체험에서 만든 잔액과 구입한 아이템도 모드 전환 후 유지됩니다. 실제 잔액부터 테스트하려면 체험 모드에서 0으로 설정한 뒤 연동하세요.
- 잔액·가방은 모든 포켓몬이 공유합니다. 아이템 진화 결과는 선택했던 시작 포켓몬의 기록에 저장됩니다. 예를 들어 캐이시를 후딘으로 진화시킨 뒤 캐이시를 다시 선택하면 후딘으로 돌아옵니다. 후딘을 직접 선택한 성장 기록은 별개입니다.
- 기존 저장 파일은 EXP와 모습을 유지하며 새 저장 형식으로 전환합니다. 과거 토큰은 소급하지 않아 새 잔액은 0입니다. **성장 초기화**는 현재 포켓몬의 EXP·아이템 진화 모습만 초기화하며, 가방·잔액은 유지하고 사용한 아이템을 환급하지 않습니다.

| 아이템 | 진화 대상 |
| --- | --- |
| 불꽃의돌 | 식스테일 → 나인테일, 가디 → 윈디, 이브이 → 부스터 |
| 물의돌 | 슈륙챙이 → 강챙이, 셀러 → 파르셀, 별가사리 → 아쿠스타, 이브이 → 샤미드 |
| 천둥의돌 | 피카츄 → 라이츄, 이브이 → 쥬피썬더 |
| 리프의돌 | 냄새꼬 → 라플레시아, 우츠동 → 우츠보트, 아라리 → 나시 |
| 달의돌 | 니드리나 → 니드퀸, 니드리노 → 니드킹, 삐삐 → 픽시, 푸린 → 푸크린 |
| 연결의끈 | 윤겔라 → 후딘, 근육몬 → 괴력몬, 데구리 → 딱구리, 고우스트 → 팬텀 |

연결의끈은 [Pokémon LEGENDS 아르세우스의 진화 방식](https://www.serebii.net/legendsarceus/evolution.shtml)을 적용했습니다. 현재는 1세대 151종 범위의 진화만 지원합니다.

`npm.cmd test`로 잔액·가방·전체 진화 경로·저장 마이그레이션을 검사하고, `npm.cmd run test:items`로 별도 테스트 프로필에서 실제 앱의 구매·사용·체험 잔액 설정·연동 모드 제한·진화 연출·재실행을 검사합니다.

## EXP와 진화 체험

- HP 바로 아래 파란 EXP 바와 레벨이 표시됩니다. Lv.1, 0 EXP로 시작합니다.
- **사용 토큰 체험**에 토큰 수를 입력하고 **추가**를 누르면 누적됩니다. 실제 사용량으로 키우려면 아래 **실제 사용량 연동**을 참고하세요.
- 체험 입력은 100토큰 = 1 EXP, 레벨당 100 EXP입니다. 1 EXP에 못 미치는 나머지도 보존합니다.
- 캐터피를 선택하고 체험 토큰 `60000`을 추가하면 Lv.7에 단데기로 진화합니다. 이상해씨는 Lv.16 → 이상해풀, Lv.32 → 이상해꽃입니다. 한 번에 여러 진화 레벨을 넘으면 중간 진화부터 순서대로 연출합니다. 돌·교환이 필요한 포켓몬은 레벨이 올라도 진화하지 않습니다.
- 초과 경험치는 다음 레벨에 반영되며 최종 형태로 진화한 뒤에도 레벨이 오릅니다. HP 잔여량 체험은 EXP에 영향을 주지 않습니다.
- 성장 기록은 `progress.json`에 자동 저장되어 앱 재실행 시 복원됩니다. 개발 실행은 `.local/`, exe 실행은 `%APPDATA%/Tokemon`을 사용합니다.
- 진화를 다시 체험하려면 우클릭 → **현재 선택한 포켓몬 성장 초기화 · Lv.1**을 선택하세요. 다른 포켓몬의 기록은 유지합니다. 초기화 전 전체 기록은 같은 폴더의 `progress-before-reset.json`에 백업됩니다. 경험치 추가·진화 진행 중에는 초기화하지 않습니다.
- 종별 이름과 진화 레벨은 PokeAPI 데이터에서 가져온 `src/species.json`에 있습니다. 토큰 변환 비율과 레벨당 EXP는 `src/tuning.cjs`에서 조정합니다. 성장 기록은 토큰 수가 아닌 EXP로 저장하므로 비율을 바꿔도 이미 얻은 경험치는 변하지 않습니다.
- 레벨·EXP는 저장 직후 바로 갱신됩니다. 기존 효과음 뒤에 팡파르가 이어지며, 팡파르 끝의 약 2.9초 무음을 제거했습니다. 한 번에 여러 레벨을 올려도 한 세트만 재생합니다.
- 진화는 레벨업 소리가 끝난 뒤 시작합니다. 진화 전 울음소리 → 편집한 진화 BGM(13.44초) → 진화 후 울음소리 → 성공 BGM 순서입니다. 각 소리가 끝나면 다음 소리가 이어지며 전체 시간은 종별 울음소리 길이에 따라 달라집니다.
- 파형의 낮은 진폭 지점에서 32ms 크로스페이드로 반복 구간을 연결하고, BGM 음량을 두 포켓몬 울음소리의 평균 체감 음량에 맞춰 보정했습니다. 동작 줄이기 설정은 시각 효과만 줄이며, 음소거 중에도 진화 애니메이션 구간은 유지합니다.
- 편집 BGM 시작 후 약 8.98초에 진화 후 포켓몬의 검은 실루엣과 반짝이는 윤곽을 표시합니다. 진화 후 울음소리가 시작될 때 본 모습과 이름을 함께 공개합니다.
- 편집 BGM 약 4.96초부터 진화 전 모습과 진화 후 검은 실루엣이 0.4초씩 번갈아 보입니다. 약 8.98초에 진화 후 실루엣으로 고정됩니다. OS 동작 줄이기 설정에서는 교차 점멸을 생략합니다.
- 첫 프레임의 불투명 픽셀 중심과 하단을 기준으로 자동 정렬하며, 피카츄·라이츄에는 기존 수동 보정값을 유지합니다. 진화 중 GIF 포즈는 고정하고, 교차할 때 공통 바닥 기준점 주위로 크기가 60~100%를 오갑니다. 특이한 체형이나 공중에 뜬 포켓몬은 추가 수동 보정이 필요할 수 있습니다.
- 스피커 버튼이나 우클릭 음소거는 울음소리, 레벨업 효과음, 진화 BGM을 모두 즉시 멈춥니다. 음원 재생에 실패해도 경험치 저장과 진화는 계속 진행됩니다.

## 실제 사용량 연동

우클릭 → **사용량 연동**에서 **체험 (수동 입력)**, **Claude**, **Codex** 중 하나를 고릅니다. 몬스터는 한 마리이며, 선택한 서비스의 새 사용량만 EXP가 됩니다.

- 서비스를 **처음 연동할 때** PC에 남아 있는 로그의 누적 사용량을 한 번에 합산합니다. 이후에는 새 사용량만 세며, 재실행하거나 서비스를 바꿔도 같은 사용량을 두 번 세지 않습니다. 다른 서비스를 선택해 둔 동안이나 앱이 꺼져 있던 동안의 사용량은 다시 선택하거나 실행할 때 한꺼번에 반영되고, 레벨업 연출은 한 번만 재생합니다. 이전 버전에서 이미 연동한 서비스는 중복 적립을 막기 위해 기존 연동 시점을 그대로 유지합니다.
- **10,000토큰 = 1 EXP**입니다(캐터피의 첫 진화까지 600만 토큰). 캐시 읽기 토큰은 세지 않습니다. 하루에 수천만 개씩 쌓여 다른 사용량을 가리기 때문입니다. Claude는 입력 + 캐시 쓰기 + 출력, Codex는 캐시되지 않은 입력 + 출력을 셉니다.
- **Codex**는 한 HP바 안에 굵은 초록 막대(5시간 잔여량)와 하단의 얇은 보라 띠(주간 잔여량)를 표시합니다. 주간 15% 이하에서는 띠가 주황색이 됩니다. 마우스를 올리면 초기화 시각과 마지막 확인 시각을 볼 수 있습니다. 주간 정보가 없으면 띠를 숨기고 미확인으로 표시합니다.
- **5시간 또는 주간 기본 할당량 중 하나라도 실제로 모두 소진하면** 흰 실루엣과 붉은 입자로 변해 발밑 포켓볼에 흡수됩니다. 던지기 없이 약 2.4초 동안 복귀하며, 닫힌 볼은 6.5초 주기로 천천히 좌우로 움직입니다. 진화 중이면 진화를 마친 후 들어갑니다. 볼도 드래그로 이동할 수 있으며 클릭해도 울지 않습니다. 한도가 조금이라도 남으면 1% 이상으로 표시해 반올림 때문에 잘못 복귀하지 않도록 합니다.
- 초기화 시각이 지나거나 새 로그에 잔여량이 확인되어 **소진된 한도가 모두 해소되면** 약 1.5초 동안 빛과 함께 나옵니다. 둘 다 소진됐다면 한쪽만 회복되어도 계속 쉽니다. 초기화 시각만으로 회복을 판단한 경우 `초기화 예상`을 표시합니다. 로그가 갱신되지 않으면 실제 잔여량과 차이가 날 수 있습니다. 소진된 한도의 초기화 시각이 없으면 새 로그를 기다립니다.
- 포켓볼은 **기본 할당량 소진**을 표현하며 계정 전체 사용 불가를 뜻하지 않습니다. 추가 크레딧·API 결제 등으로 계속 사용한 토큰은 EXP에 반영됩니다. 볼 안에서는 성장 연출을 생략합니다. 앱 재시작 시에는 로그로 휴식 상태를 복원하고, 연동 서비스를 바꾸면 이전 서비스의 휴식 상태를 해제합니다.
- **Claude**는 아직 EXP만 연동합니다. 남은 한도를 읽는 공식 경로가 마땅치 않아 HP는 체험 슬라이더로 둡니다.
- 연동 중에는 체험용 토큰 입력칸이 숨겨지고 입력도 거부됩니다.

사용량은 각 도구가 이 PC에 남기는 로그에서 읽습니다. 숫자 필드만 읽고 대화 내용은 읽지 않으며, 어떤 데이터도 외부로 보내지 않습니다.

| | 읽는 위치 | 세는 방법 |
|---|---|---|
| Claude Code | `~/.claude/projects`, `~/.config/claude/projects`, `CLAUDE_CONFIG_DIR` | 같은 메시지가 스트리밍 중 여러 번 기록되므로 메시지 ID별로 가장 큰 값을 씁니다. 서브에이전트 파일(`subagents/`)도 포함합니다. |
| Codex | `~/.codex`, `CODEX_HOME`, Orca의 Codex 홈 아래 `sessions`·`archived_sessions` | 응답마다 한 줄씩 남는 `token_usage_record`를 응답 ID별로 합산합니다. 이 기록이 없는 구버전 로그는 `token_count`의 호출별 사용량을 씁니다. 세션 누적값은 중간에 초기화되므로 쓰지 않습니다. |

한계: Claude Code와 Codex CLI·앱이 로그로 남긴 사용량만 잡힙니다. claude.ai 웹 채팅처럼 로그가 없는 사용량은 플랜 한도에는 포함되지만 EXP에는 반영되지 않습니다. 두 로그 형식 모두 공식 지원 대상이 아니어서 도구가 업데이트되면 읽기가 멈출 수 있고, 그때도 앱과 기존 성장 기록은 그대로 동작합니다. 선택한 서비스와 반영 내역은 `usage.json`에 저장합니다.

## 개발

`npm.cmd run check`로 JavaScript 구문을 검사합니다.

151종 데이터·리소스 갱신은 `python scripts/import-kanto.py`로 실행합니다(네트워크 필요). 기존 리소스는 유지하고 누락 파일을 다운로드합니다. 단위 테스트는 모든 레벨 진화 경계, 종별 저장·복원·초기화와 기존 저장 파일 이관을 검증합니다. 브라우저 검사는 151종 GIF와 음원을 실제 Chrome에서 디코딩하고 선택 기능을 검증하며 `.local/kanto-catalog.png`에 전체 미리보기를 저장합니다.

`npm.cmd test`는 경험치 경계, 여러 레벨 상승, 직렬 저장, 잘못된 입력 및 재시작 후 복원과 함께 사용량 집계 규칙(중복 제거, 서브에이전트, 연동 시점, 이어 읽기, 재시작, Codex 한도)을 검사합니다. `npm.cmd run test:smoke`는 별도의 임시 프로필에서 EXP → 진화와 화면 재로드 후 복원, 사용량 연동까지 검증합니다. 연동 테스트는 임시 로그만 읽으므로 사용자의 성장 기록과 실제 사용량 로그를 건드리지 않습니다.

빌드 후 `node scripts/packaged-smoke.cjs`로 실제 포터블 실행 파일의 오프라인 리소스 로딩(두 몬스터와 성장 효과음), 애니메이션, 기절 및 회복을 검사할 수 있습니다. Node.js 22 이상과 비어 있는 로컬 포트 19387이 필요합니다.

`npm.cmd run test:smoke`는 실제 Electron 창에서 GIF 프레임 디코딩, 오디오 재생 상태, 합성 포인터 이벤트에 따른 창 이동, 클릭/드래그 구분, 음소거, 상태 경계값, 기절 시 정지·무음 및 회복을 검사합니다. 실행 중인 앱을 종료한 후 실행하세요. 실제 마우스 조작과 스피커 출력은 별도로 확인해야 합니다.

`npm.cmd run test:recall`은 임시 로그로 이중 HP, 5시간·주간 각각의 소진·초기화와 동시 소진 후 회복 조건, 포켓볼 복귀·대기·재등장, 재로드와 연동 변경을 검사합니다. `npm.cmd run test:browser`는 설치된 Chrome에서 같은 화면 코드와 번들 리소스로 애니메이션·진화 순서·동작 줄이기를 검사하는 대체 검사입니다. 이때 Electron 연결부만 가짜 데이터로 대체하므로 네이티브 창 이동이나 실제 로그 연동은 검증하지 않습니다. 필요하면 `TOKEMON_TEST_BROWSER`에 Chrome/Edge 실행 파일 경로를 지정합니다. 화면 캡처는 `.local/recall-*.png`에 저장됩니다.

### Windows에서 `spawn UNKNOWN`으로 실행되지 않는 경우

이 메시지는 Electron 실행 실패를 감싼 오류입니다. `node_modules/electron/dist/electron.exe` 직접 실행 시 Application Control 차단이 표시되고 Windows CodeIntegrity 로그에 이벤트 3077/3033이 있다면 앱 코드가 실행되기 전에 보안 정책이 막은 것입니다. 개발 PC에서는 서명 없는 Electron 41.10.7에 대한 Smart App Control 차단을 확인했고, 사용자가 해당 설정을 끈 후 Electron 검사가 정상 실행됐습니다. 이 프로젝트는 Windows 보안 설정을 자동 변경하지 않습니다. 보호 설정을 유지해야 하는 환경에서는 정책에 허용되는 서명된 실행 파일이나 관리자의 정책 검토가 필요합니다.
